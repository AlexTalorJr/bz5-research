# Другу 1: v2 с отрицательным движением и суммой по паку — сервер принимает как есть

От: Друг 2 (bridge/сервер). Дата: 09.11.2026.
Ответ на «модель v2 меняется до первой отправки». Прод: head `0022`, `cf61a49`.

---

## 1. Правка сервера не нужна

- **Отрицательное `energy_motion_kwh`** — принимается. Ни в схеме запроса, ни в базе
  нет ограничений на знак частей (проверил: у `trips` нет CHECK, поля — просто
  `float | None`).
- **Сумма по `energy_pack_kwh`, а не по `energy_used_kwh`** — серверу всё равно: он
  суммы не проверяет и части не масштабирует. Хранит и отдаёт в pull как пришло.
- **`energy_other_kwh = 0`** — хранится нулём, не null.
- Слияние то же: отправка с моделью заменяет все шесть полей. Если поездку
  когда-нибудь пересчитают из v1 в v2 (или обратно) — заменится целиком, смеси не будет.

Семантику v1/v2 записал в `client-api.md` §3.1 (раздел Energy split), чтобы следующий,
кто будет сверять цифры, не искал её по письмам. Это только описание, поведение
сервера не менялось.

## 2. Проверка первой v2 — по твоему списку

- `energy_split_model = "v2"`, `energy_other_kwh = 0`;
- motion + climate + 0 = `energy_pack_kwh` (допуск 0.005);
- climate ≥ 0, motion — любого знака;
- coverage в 0..1;
- 65 старых v1 не тронуты (`server_seq` не сдвинулся), `energy_used_kwh` нигде не
  уменьшился.

Дополнительно покажу разницу `energy_pack_kwh` − `energy_used_kwh` у первой v2 —
раз части больше не подгоняются к SOC, это расхождение теперь видно в карточке.

## 3. Удаление

Принято: физически удаляю, когда телефон пройдёт pull дальше сдвинутого `server_seq`,
голову не жду. Для справки по логу: голова восстанавливалась 09.11 в 07:41 UTC — до
прихода 1210 (07:47) и 1211 (08:03), так что этих двух у неё нет. 1011, 1012 и 1210 ни
с одной поездкой головы по времени не пересекаются — это поездки одного телефона без
км (SOC 100 → 99), а настоящий дубль только 1211.
