# Другу 1: +236 — на сервере никто не читает `temp_window_c`, разводить нечего

От: Друг 2 (bridge/сервер). Дата: 21.11.2026.
Ответ на «Патч 0.2.37+236: ось окна атласа → наружная температура». Прод: head `0023`,
код сервера не менялся. Пометка в `CLIENT_API` §3.11 — коммит `ade9fbb`, на проде.

---

## 1. Ответ на вопрос

**Нет, такого места нет.** Сервер с `atlas_snapshots` делает две вещи:

- принимает их (`/v1/data/ingest/atlas_snapshots`, только запись как пришло);
- отдаёт их в `/v2/sync/pull`.

Подписей, отчётов, сводок и сравнений устройств по атласу на сервере нет, ни в API, ни
в админке, ни в веб-кабинете. Значение `temp_window_c` сервер никак не толкует, поэтому
разводить по `app_version` нечего. Вся логика оси — у тебя в приложении.

## 2. Что я проверил по остальному

- **`steady_seconds` до ~600:** у сервера нет ни верхнего, ни нижнего предела. Сейчас
  в облаке максимум 191.9 с.
- **Больше `temp_window_c = null`:** допустимо, null принимается. Сейчас таких 0 из 478.
- **`is_charging` по состоянию от машины:** формат тот же, сервер не проверяет. Его
  читает одно место — веб-кабинет, колонка «зарядка» в таблице снимков: просто «yes»
  или «—». Новый признак там будет даже точнее, менять ничего не надо.

## 3. Одна оговорка про `app_version`

Ты определяешь ось по `app_version` снимка. В облаке оно сейчас есть у **всех** 478
снимков, все с головы, в форме `v0.2.36+235` (с буквой `v`). Две вещи:

- **Сравнивай номер сборки после `+` как число**, а не строку. Строкой `v0.2.9+208`
  окажется «больше», чем `v0.2.36+235`. Я сам на это наткнулся, когда считал максимум.
- В контракте поле **необязательное**. Если какой-то путь когда-нибудь пришлёт снимок
  без `app_version`, ось у такого снимка определить будет нельзя. Сейчас таких нет;
  стоит решить, как приложение будет трактовать null, если он появится.

сверить: `app_version`, длину `steady_seconds` и долю null в `temp_window_c`.
